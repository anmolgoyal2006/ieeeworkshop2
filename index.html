    💀 Debugging — When Code Breaks

    Your code WILL break. That's part of programming.

    🐛 Spot the bug:

    int marks = 50; if (marks = 40) cout << "Pass";
    Fix: marks = 40 → marks == 40
    = assigns a value  |  = = compares two values

    3 Types of Errors

    SYNTAX ERROR

    Code violates language rules. Missing ;, typo in keyword. Caught at compile time — easiest to fix.

    RUNTIME ERROR

    Compiles but crashes while running. Dividing by zero, accessing invalid memory.

    LOGICAL ERROR

    Runs fine but gives wrong output. Hardest to catch. Using = instead of = = is a classic one.

    😤
    "Missing semicolon"
    One tiny ; — one huge problem. Every developer's rite of passage.
    SLIDE 14 — DEBUGGING (~3 min) "Your code WILL break. Not might. WILL. Every single developer's code breaks." "Spot the bug — 20 seconds." Ask the room. Click Find the Bug. Walk through the = vs == distinction. MCQ: Answer B — = is assignment, == is comparison. "This is THE most common beginner mistake. Experienced devs still occasionally write it." Show 3 error types quickly. Don't dwell on each. KEY MESSAGE: "Errors don't mean you're bad at programming. Errors mean you ARE programming." [Presenter: 'I once spent 2 hours because of a missing semicolon. We all have that story.'] Transition: "Okay — you've now seen the full picture. Let's zoom out and see where all this leads."
